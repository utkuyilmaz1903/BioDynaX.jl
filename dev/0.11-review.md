### Findings that need a reviewer's eye

1. No library recovers the full true support. Every graph-local candidate
   is a polynomial in R with an empty denominator (seed 103, no noise:
   `-0.11 + 2.05 R - 0.62 R^2`; seed 113, noise 0.02: `1.86 R - 0.52 R^2`),
   so `R^2` is found in the numerator, the denominator `R^2` never, and
   recall is 0.5 in all 15 runs. The reference protocol's recall 1.0 is on
   the two-state network with a one-variable library; on this four-state
   fixture the library includes S and the implicit fit settles on a
   quadratic approximation of the saturating rate over the sampled range
   R in [0.1, 2]. The docs state this. Nothing about the discovery
   configuration was changed to improve it.
2. The ordering graph-local, then global, then wrong graph holds at every
   noise level for F1, recall, extras, and held-out residual, which is
   what the central claim needs; the claim as stated on the benchmarks page
   is "more reliably", not "exactly".
3. Three rows have infinite residuals because the discovered polynomial
   rate makes the hybrid model diverge on the trajectory. The medians are
   over finite values and the page says so.

### Decisions

- Kept the full noise set; no scope reduction was needed.
- The residual of a study candidate uses a full-state composition written
  in the study module (`_library_study_hybrid_rhs`), because study
  candidates are regressed on all four states while `compose_hybrid_rhs`
  passes only the term's regulators. `compose_hybrid_rhs` and
  `hybrid_data_residual` are untouched.
- `evaluate_trained_graph_local` gained `seed` and `noise_σ` keywords whose
  defaults are the existing constants. Verified against a fingerprint of
  the smoke run recorded on unmodified `main` before the change: network
  parameter fingerprint 7841976074244207967, sampled-rate hash
  2158718377550760976, coordinate hash 5552514529174960623, the three
  discovered supports, and the physical parameters are identical after the
  change. The test suite asserts that the default call equals the call
  with the explicit default values.
- Test cost: the new test file has 120 assertions and takes 55 s inside
  `Pkg.test()`; the full suite passed with 449 testsets in 15 minutes.

## Phase 1 addition: the recall gap between the study and the reference protocol

### Step 1: configuration differences (from the code)

The four-state study scores discovery through `evaluate_trained_graph_local`,
the reference protocol through `_evaluate_unknown_rate_recovery`. Both use
`rate_discovery_config` (implicit SINDy-PI, threshold 1e-3, polynomial degree
2, Hill degree 2, validation fraction 0.2, 32 domain samples, chunk size 32,
no interaction terms), so the thresholds and degrees are identical. Every
other setting differs:

| Setting | Four-state study (`:study` variant) | Reference protocol |
|---|---|---|
| Network | S, R, Q, Z; Hill degradation of S by R; distractor Z | S, R; Hill degradation of S by R |
| Training data | 3 initial conditions, 40 points, all used for training | 9 initial conditions, 50 points, 7 used for training |
| Sample coordinates | 80 designed points: S fixed at 0.4, R on [0.1, 2.0], Q and Z noisy functions of R | 80 points of R on the regulator grid of the training experiments |
| States regressed | the learned rate against all states of the library | the learned rate against R only |
| Library variables (graph-local) | S and R: `local_basis` always includes the target state, and S is constant across the samples, so its column is collinear with the constant term | R only: `discover_unknown_rate` builds a one-node network from the R samples |
| Denominator candidates | S, S^2, R, R^2 (every non-constant monomial) | R, R^2 |
| Bootstrap | `bootstrap = 0`: `_consensus_refit` degenerates to one thresholded fit and `prune_nested_implicit` is never called | `bootstrap = 8`: block bootstrap, consensus refit at frequency 0.8, nested-monomial pruning by held-out error |
| Sample order before the validation split | as generated, R ascending: the contiguous validation block is the 16 largest R values | permuted with the discovery seed |
| Discovery seed | 11 | 3 |

So the four-state library does contain the denominator candidate `R^2`;
step 3's hypothesis (missing denominator candidates) does not hold and no
keyword for it was added. The candidates that differ are the target state
S in the library, the bootstrap (and with it the nested pruning), and the
sample permutation. To separate them the study function gained discovery
`variants`, all computed on the same learned-rate samples of one training:
`:study` (as above), `:bootstrap` (same libraries, reference bootstrap,
unpermuted), `:parents` (parent-only libraries, no bootstrap, unpermuted),
and `:reference` (parent-only libraries, reference bootstrap and seed,
permuted; for the graph-local library this is `discover_unknown_rate` with
`rate_discovery_config()`, the reference protocol's call). It also gained a
`:two_state` fixture that trains the reference network with the reference
protocol (nine initial conditions, 7/2 split, Adam 100 then BFGS 50, the
truth parameters of `run_recovery_suite`) and samples the learned rate on
the regulator grid of the training experiments, with S spread over its
observed range in a fixed shuffled order so that S and R are not collinear.
