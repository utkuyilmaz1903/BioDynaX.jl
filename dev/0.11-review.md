### Findings that need a reviewer's eye

1. No library recovers the full true support. Every graph-local candidate
   is a polynomial in R with an empty denominator (seed 103, no noise:
   `-0.11 + 2.05 R - 0.62 R^2`; seed 113, noise 0.02: `1.86 R - 0.52 R^2`),
   so `R^2` is found in the numerator, the denominator `R^2` never, and
   recall is 0.5 in all 15 runs. The reference protocol's recall 1.0 is on
   the two-state network with a one-variable library; on this four-state
   fixture the library includes S and the implicit fit settles on a
   quadratic approximation of the saturating rate over the sampled range
   R in [0.1, 2]. The docs state this. Nothing about the discovery
   configuration was changed to improve it.
2. The ordering graph-local, then global, then wrong graph holds at every
   noise level for F1, recall, extras, and held-out residual, which is
   what the central claim needs; the claim as stated on the benchmarks page
   is "more reliably", not "exactly".
3. Three rows have infinite residuals because the discovered polynomial
   rate makes the hybrid model diverge on the trajectory. The medians are
   over finite values and the page says so.

### Decisions

- Kept the full noise set; no scope reduction was needed.
- The residual of a study candidate uses a full-state composition written
  in the study module (`_library_study_hybrid_rhs`), because study
  candidates are regressed on all four states while `compose_hybrid_rhs`
  passes only the term's regulators. `compose_hybrid_rhs` and
  `hybrid_data_residual` are untouched.
- `evaluate_trained_graph_local` gained `seed` and `noise_σ` keywords whose
  defaults are the existing constants. Verified against a fingerprint of
  the smoke run recorded on unmodified `main` before the change: network
  parameter fingerprint 7841976074244207967, sampled-rate hash
  2158718377550760976, coordinate hash 5552514529174960623, the three
  discovered supports, and the physical parameters are identical after the
  change. The test suite asserts that the default call equals the call
  with the explicit default values.
- Test cost: the new test file has 120 assertions and takes 55 s inside
  `Pkg.test()`; the full suite passed with 449 testsets in 15 minutes.

## Phase 1 addition: the recall gap between the study and the reference protocol

### Step 1: configuration differences (from the code)

The four-state study scores discovery through `evaluate_trained_graph_local`,
the reference protocol through `_evaluate_unknown_rate_recovery`. Both use
`rate_discovery_config` (implicit SINDy-PI, threshold 1e-3, polynomial degree
2, Hill degree 2, validation fraction 0.2, 32 domain samples, chunk size 32,
no interaction terms), so the thresholds and degrees are identical. Every
other setting differs:

| Setting | Four-state study (`:study` variant) | Reference protocol |
|---|---|---|
| Network | S, R, Q, Z; Hill degradation of S by R; distractor Z | S, R; Hill degradation of S by R |
| Training data | 3 initial conditions, 40 points, all used for training | 9 initial conditions, 50 points, 7 used for training |
| Sample coordinates | 80 designed points: S fixed at 0.4, R on [0.1, 2.0], Q and Z noisy functions of R | 80 points of R on the regulator grid of the training experiments |
| States regressed | the learned rate against all states of the library | the learned rate against R only |
| Library variables (graph-local) | S and R: `local_basis` always includes the target state, and S is constant across the samples, so its column is collinear with the constant term | R only: `discover_unknown_rate` builds a one-node network from the R samples |
| Denominator candidates | S, S^2, R, R^2 (every non-constant monomial) | R, R^2 |
| Bootstrap | `bootstrap = 0`: `_consensus_refit` degenerates to one thresholded fit and `prune_nested_implicit` is never called | `bootstrap = 8`: block bootstrap, consensus refit at frequency 0.8, nested-monomial pruning by held-out error |
| Sample order before the validation split | as generated, R ascending: the contiguous validation block is the 16 largest R values | permuted with the discovery seed |
| Discovery seed | 11 | 3 |

So the four-state library does contain the denominator candidate `R^2`;
step 3's hypothesis (missing denominator candidates) is false and no
keyword for it was added. The candidates that differ are the target state
S in the library, the bootstrap (and with it the nested pruning), and the
sample permutation. To separate them the study function gained discovery
`variants`, all computed on the same learned-rate samples of one training:
`:study` (as above), `:bootstrap` (same libraries, reference bootstrap,
unpermuted), `:parents` (parent-only libraries, no bootstrap, unpermuted),
and `:reference` (parent-only libraries, reference bootstrap and seed,
permuted; for the graph-local library this is `discover_unknown_rate` with
`rate_discovery_config()`, the reference protocol's call). It also gained a
`:two_state` fixture that trains the reference network with the reference
protocol (nine initial conditions, 7/2 split, Adam 100 then BFGS 50, the
truth parameters of `run_recovery_suite`) and samples the learned rate on
the regulator grid of the training experiments, with S spread over its
observed range in a fixed shuffled order so that S and R are not collinear.

Note on the two-state fixture: `build_hill_recovery_network` declares its
unknown term as a reaction only, and the interaction graph of a
`BiologicalNetwork` is built from `EdgeSpec`s, so `local_basis` sees no
parents for S on that network and its graph-local library is {S}. The
reference protocol never meets this because `discover_unknown_rate`
regresses on the R samples directly. The study's two-state discovery
networks therefore declare the unknown edge (R -> S, or S -> S for the
wrong graph) for library construction; training uses the reference network
unchanged. On a two-state network the graph-local and global libraries
coincide ({S, R}), which the two-state table shows.

## Phase 2: stability-selection pruning

### Design

`StabilitySelection(; n_boot = 100, τ = 0.8, seed = 7)` is a second stage
applied to the candidate the existing pipeline produces (that pipeline
already has a block bootstrap with a consensus refit at frequency 0.8 when
`bootstrap_samples > 0`, and the reference protocol's nuisance terms `1`
and `r` survive it). The stage resamples the training rows with
replacement, repeats the thresholded fit per resample, keeps candidate
terms whose frequency reaches τ, refits and revalidates them, and falls
back to the fitted candidate when it would remove every numerator term or
make the denominator unsafe. Its RNG is separate from the pipeline's, so
the candidate it starts from is the unchanged one.

Verification with the option off, before and after the change, on four
analytical fixtures (clean Hill rate, Hill rate plus `0.04 + 0.04 r`,
0.5% multiplicative noise, the nuisance case with the reference bootstrap):
numerator and denominator coefficients, frequencies, validation error, and
denominator minimum identical to the last digit. With the option on, on
these fixtures every candidate term is selected in 100 of 100 resamples,
so nothing is pruned there: the nuisance terms of the additive fixture are
stable, not spurious. The study evaluation (below, once the runs finish)
is the real test.

## Phase 3: one-call entry point

`discover_unknown_term` was verified against the chained calls of
`examples/unknown_inhibition.jl` on the reference fixture (nine
experiments, Adam 3 / BFGS 1, `holdout = 0`): network-parameter
fingerprint, physical parameters, regulator grid, learned-rate samples,
equations, identifiability collinearity, residual, and extras identical.
The full-protocol run with `holdout = 0` reproduced the tutorial's
published report line for line (residual 0.001777, the same coefficients);
with the default `holdout = 2` the report is the one now shown first in the
tutorial (residual 0.001778 on experiment 1, 0.001264 mean over the
training experiments, 0.002513 mean over experiments 8 and 9). Runtimes
under load (seven Julia processes on four cores): 7.5 minutes for the
reference protocol, 6.4 minutes for the README quick start; the quick
start rerun on the idle machine took 2.7 minutes, which is the figure the
README quotes.

Decisions: the default `discovery` configuration is the reference
protocol's (`rate_discovery_config()`, bootstrap 8, seed 3) rather than
`DiscoveryConfig()`, and the default `training` is Adam 100 / BFGS 50,
because the entry point has to reproduce the tutorial with its defaults;
`known_support` is the only way the report can list extra terms and is
documented as synthetic-data only; `report` is exported as asked, although
the name is generic.

### What explains the recall gap

The library construction, not the bootstrap, the permutation, or the
denominator candidates. On the same trained models and samples, the
study's library (target state S included, and S constant at 0.4 on the
designed coordinates) gives recall 0.5 in 15 of 15 runs with or without
the reference bootstrap; the parent-only library gives recall 1.0 in 15 of
15 runs with the reference protocol's extras `1` and `R`, with or without
the bootstrap and permutation. The two-state fixture, whose library also
contains S but samples it over its observed range, reaches recall 1.0 in
every variant, which points at the constant column rather than at the
presence of the target state. Not run: a four-state variant with S varying
over the designed coordinates, which would settle that last point; it
needs a new coordinate design and was left for the reviewer to decide.

Step 3 did not apply (the denominator candidates are present in both
configurations), so no keyword was added for it. The parent-only library
is available as `variants = (:parents,)` or `(:reference,)`; the default
variant of the study and the behaviour of `evaluate_trained_graph_local`
are unchanged. The central claim (graph-local before global before wrong
graph) holds in all four variants on both networks; with parent-only
libraries the global library also recovers the true support but with five
extra terms and a residual five to eight times larger.

Pruning never reduced recall. It removed the constant or `S^2` term of the
four-state study rows (leaving `R`) and the linear term of one two-state
reference row (seed 127, noise 0.02, F1 0.67 to 0.80). It did not remove
the reference protocol's `1` and `R` anywhere else: they are selected in at
least 80% of row resamples. Conclusion recorded on the benchmarks page:
the option does not raise F1 on the reference protocol, it is kept, off by
default, and τ was not tuned per case (rule 5). Cost: 100 thresholded fits
per discovery, well under a second on 80 samples.
